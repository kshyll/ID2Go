# ID2Go – Student ID Appointment and Queue Management System

ID2Go is a mobile application developed for Xavier University – Ateneo de Cagayan to streamline student ID appointment scheduling, queue monitoring, and camera station management.

## Technology Stack

- **Frontend:** HTML, CSS, JavaScript
- **Framework:** Apache Cordova
- **Planned Backend:** Supabase
- **Planned Database:** PostgreSQL
- **Version Control:** Git and GitHub

## 1. Application Build

**Current Status:** UI/UX Prototype and Integration

The project includes developed interfaces for appointment booking, queue management, and camera operator operations. Shared navigation and student profile functionality are being integrated.

A complete, verified mobile application build is still pending.

## 4. Development Progress Report

### Completed Features

| Feature | Current Implementation |
|---|---|
| Cordova Setup | Initial project structure and configuration |
| Appointment Booking | Service selection, student information form, scheduling, and confirmation UI |
| Student Queue | Queue status, appointment details, and station monitoring UI |
| Queue Management | Queue listing and processing controls with demonstration data |
| Camera Operator | Station selection, student calling, arrival confirmation, and service completion prototype |
| GitHub Collaboration | Feature branches and development integration workflow |

### In Progress

| Feature | Current Progress |
|---|---|
| Student Login | UI-only role selection; authentication not implemented |
| Student Profile | Local profile information and navigation |
| Page Navigation | Connecting login, queue, booking, and profile interfaces |
| Module Integration | Standardizing navigation and data handling between independently developed modules |

### Planned Features

- Secure authentication and role-based access.
- Supabase and PostgreSQL integration.
- Real-time appointment and queue synchronization.
- Automatic queue number generation and station assignment.
- Integration of booking records with camera operator operations.
- Appointment notifications and queue alerts.
- Booking eligibility and duplicate-service restrictions.
- System administrator dashboard.
- End-to-end testing and verified mobile application build.

### Problems Encountered

- Git branch conflicts during feature integration.
- Inconsistent navigation between independently developed pages.
- Separate data handling across booking, queue, and operator modules.
- Incomplete backend connectivity.

### Solutions Applied

- Organized code using feature branches and a shared development branch.
- Introduced a shared navigation structure.
- Used local storage and demonstration data for UI testing.
- Identified common data requirements for future backend integration.
